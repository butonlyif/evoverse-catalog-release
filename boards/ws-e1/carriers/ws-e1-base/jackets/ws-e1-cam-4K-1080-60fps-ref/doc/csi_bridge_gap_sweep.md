# CSI-2→HDMI 桥片行/帧间距接受域扫频实验方案

（2026-10-19 立项；shape_pat_gen gap 注入，'v' 直注通路实施）

## 1. 背景与动机

- v3 DDR 回放架构 camera 模式显示器报"无输入信号"。DIAG18 窗口版实测
  显示帧率 55.4Hz（df/fw = 28.8/31.3 = 0.92，跨 11 窗严格恒定），非标
  帧率 → 桥片拒锁。根因已定位：frame_reader 的 dos_seen 电平闩锁使
  reader 锁到相机节奏（60fps）而非显示节奏（60.000Hz），每帧多喂 ~8
  行，shape 门排积压把帧拉长到 2250+~190 tick 自持平衡（已改 dos_pulse
  沿放行，待板测）。
- 未决问题：**桥片到底接受什么时序？** Vtotal（帧率）下界在哪？
  Htotal（行周期）上界在哪？需要一个完全受控的激励源直接扫这两个维度。
- 'v' 直注通路（shape_pat_gen → shape → TX → 桥片）已实证 60.000Hz
  出图，是干净的激励点：在源注入受控间隔，桥片看到的就是纯间隔变量。

## 2. 实验原理

### 2.1 旋钮 → 桥片可见量的映射

| 旋钮 | 单位 | 行/帧周期 | 间隙落点 | 桥片可见量 |
|---|---|---|---|---|
| 行间距 g_l | 拍（1 拍 = 1 pixel_clk = **4 px**） | 行周期 = (1100+g_l) 拍 | HBP 拉伸 | **Htotal = 4×(1100+g_l) px** |
| 帧间距 g_f | tick（1 tick = 1100 拍 = 1 行） | 帧周期 = 2160×行周期 + (90+g_f) tick | VBP 停留段拉伸 | **Vtotal = 2250+g_f 行** |

### 2.2 Htotal ÷4 的结构保证

TX 侧全流水线 4 像素/时钟（shape 按时钟计数、TX 每时钟发 4px），
间隔以时钟数为单位 ⇒ **Htotal(px) = 4×时钟数恒被 4 整除**，不依赖
参数取值。拍是 4px 管线中可实现的最高粒度（更细的间隔物理上不存在）。

### 2.3 行连续性契约不破坏

行内 960 拍数据背靠背不变（shape_video_axis 行发射硬契约），全部
间隙落在消隐段：行间隙在 Hback（HBP），帧间隙在 Vback 停留段（VBP）。

### 2.4 行周期均匀性（关键实现细节）

不能"等 N 个 tick 再等 G 拍"——tick 相位固定，行起始相对 tick 漂移
会造成行周期锯齿（1100+G 与 2200+G 交替），桥片看到抖动 Htotal。
行尾等待用双条件：

```
行尾等待态：if ((line_elapsed >= 1100 + line_gap) && tick_seen) 启动新行
```

- g_l=0：退化为"elapsed≥1100 且见过 tick" = 现行 tick 锚定行为逐拍
  等价，**60.000Hz 基线零回归**
- g_l>0：窗口 >1100 拍必含至少一个 tick，elapsed 条件主导，行周期
  严格均匀 = 1100+g_l 拍

### 2.5 帧率换算

```
帧周期(拍) = 2160×(1100+g_l) + (90+g_f)×1100
fps       = 148.5e6 / 帧周期
```

g_l=0 时帧间距与帧率对照（扫频速查）：

| g_f (tick) | fps    | g_f | fps    | g_f | fps    |
|---|---|---|---|---|---|
| 0   | 60.000 | 100 | 57.447 | 185 | **55.428**（复现拒锁点） |
| 25  | 59.341 | 125 | 56.842 | 200 | 55.100 |
| 50  | 58.696 | 150 | 56.250 | 250 | 54.000 |
| 75  | 58.065 | 175 | 55.670 | 300 | 52.941 |

板测读数：DIAG18 `cnt: df`（0.75s 固定窗）应 ≈ 0.75×fps（60Hz=45）。

## 3. 设计规格（RTL）

### 3.1 shape_pat_gen.sv

- 新端口：`line_gap[15:0]`（拍）、`frame_gap[15:0]`（tick）
- 行尾等待态改双条件（见 2.4）；`line_elapsed` 11bit 复位清零，
  每 `tick_seen` 判定后重新计数
- pad 段计数 8bit→17bit：计 tick 至 `(90 + frame_gap)` 后发车行 0
  （保留 pad 差一拍修复语义：计满后下一 tick 发车，帧长恰如公式）
- 范围：g_l 至 65535 拍 → 行周期 493µs；g_f 至 65535 tick → 帧周期
  ~0.5s（约 2Hz）

### 3.2 shape_video_axis.sv

- `SOF_WAIT_TIMEOUT_LINES` 90 → **1023**，`gate_wait_lines` 8→10bit
- 原因：g_f>90 时 sof 每帧迟到超窗 → 超时+fifo_flush 每帧触发，既污染
  时序又毁内容，实验在 57.7Hz 以下全部失效。加宽后 g_f≤1023 全程干净
- 副作用仅异常路径：真断流时 flush 恢复从 1.2ms 变 17ms

### 3.3 apb_cam_ctrl.sv

- 新增 **CTRL2 @0x08**（复用退役 DIAG2 槽，可读写，复位 0）：
  - `[15:0]` line_gap（拍）
  - `[31:16]` frame_gap（tick）
- 写译码从 `~paddr[2]` 改为按 `paddr[6:2] ∈ {5'd0, 5'd2}`

### 3.4 camera_path.sv / top_cam.sv

- camera_path 新端口 `pat_line_gap/pat_frame_gap` 直通 u_shape_pat
  （DBG_SHAPE_PAT generate 内）；top_cam 从 apb 引两条 wire

## 4. 固件（sw/top_demo/src/main.c + userDef.h）

- `userDef.h`：`#define CAMC_REG_CTRL2 0x08`（DIAG2 退役转正）
- 键位（作用于 `[`/`]` 选中的目标路）：

| 键 | 功能 | 步进 | 粒度 |
|---|---|---|---|
| `u` / `j` | 帧间距 +/− | GAP_FRAME_STEP = **10 tick** | 0.267Hz/按 |
| `n` / `m` | 行间距 +/− | GAP_LINE_STEP = **10 拍** | 40px = 0.9%行周期/按 |

- 步进为 main.c 顶部 `#define`，扫频中可改重编
- 每按打印：`gap: line=%d(%dus,%dpx) frame=%d fps~%d`（行周期 µs、
  Htotal px、估算帧率）
- `x` 键复位默认时同时清零两个 gap；CTRL2 写入在 cam_apply 内，
  不触发 sw_src 软复位，运行中改值帧界后即生效
- 只影响 'v' 直注源；camera/pattern 路径零改动

## 5. 操作步骤（SOP）

1. 重综合（RTL：shape_pat_gen/shape_video_axis/apb_cam_ctrl/
   camera_path/top_cam）+ 重编固件，上电出图案
2. 按 `v` 开直注源，确认出图（基线 60.000Hz，`cnt: df=45`）
3. **帧域扫频**：连按 `u` 递增 g_f，每按观察屏 + `cnt: df`；记录黑屏
   临界 g_f* → 桥片帧率下界 = 148.5e6/(2475000+1100×g_f*)
4. **裁决 55.4Hz 案例**：临界帧率若 >55.4Hz，证实 camera 模式拒锁纯因
   帧率（reader 沿放行修复方向正确）；g_f=185 一档即 55.43Hz，可精确
   复现拒锁条件做 A/B
5. **行域扫频**：g_f 回 0，按 `n` 递增 g_l，记录黑屏临界 g_l* →
   Htotal 上界 = 4×(1100+g_l*)；注意帧率同步下滑，若临界帧率仍高于
   第 3 步下界，则黑屏归因 H 因素
6. **组合域（可选）**：固定小 g_l 再扫 g_f，看帧率边界是否随 Htotal
   移动（H/V 交互项）

## 6. 判读表

**2026-10-19 板测边界确定**：步进取 1 tick 后逐档实测——
g_f=0/1/2（Vtotal 2250/2251/2252，60.000/59.973/59.947Hz）**全部锁**；
g_f=3（Vtotal 2253，59.920Hz）**无信号**。每档期间 df=45/45、
uflow=+1/帧（g_f 行迟到 sof 门停留）、srch 冻结、lost=0。
**桥片容差 = +2 行 = +0.089%（帧率下界 59.947Hz），第 3 行即拒。**
=> frame_reader 沿放行修复（残余拉伸 ~0.1~1.4 行）在预算内，
camera 模式应可直接锁定。

**2026-10-19 板测第一点**：`u` 一次（g_f=10 → Vtotal 2260，59.729Hz）
即黑屏无信号；**按 `j` 回 g_f=0 立即恢复出图**（黑屏不粘滞，桥片在
60.000Hz 瞬间重锁，扫频可快速迭代）。板侧证据链全部自洽：df=45,45,
45,44,44/0.75s 窗（=44.78 帧理论值精确）、uflow+31/0.5s 窗（每帧 1 次
门停留 = sof 迟 10 行）、srch 冻结（行对齐零破坏）、lost=0（FPGA 在
干净发完整流）。

| 现象 | 结论 | 下一步 |
|---|---|---|
| g_f* 对应 ~55-56Hz | 拒锁纯因帧率，与 55.4Hz 实测吻合 | 板测 camera 模式（沿放行后应锁 59.95+） |
| g_f* 很小（1~10） | 容差极紧（<1%），59.95Hz 修复余量存疑 | g_f=1 通 => reader 修复够；黑 => 需 reader 预发车（消隐起点脉冲 + reader 去 tick 从动） |
| g_l 增大即黑屏且帧率仍够 | 桥片不容忍 Htotal 拉伸 | 归档；检查现有时序 H 余量（HBP=296px 固定，无拉伸风险） |
| g_l 大范围可接受 | 桥片 H 容差宽 | 归档边界值即可 |
| 任何 g_f>0 都立即黑屏 | 桥片锁死后不容忍帧率漂移，或 VBP 拉伸不容忍 | g_f 改注入 VFP 侧（Vfront 段）复测 |

## 7. 已知限制

- 行 gap 增大时帧率同步下滑（2160 行×每行增量），H 维度不独立——
  解读必须对照第 3 步得到的帧率下界
- 门停留超时加宽到 1023 行后，真断流的显示恢复变慢（17ms），
  仅异常路径受影响
- 本实验只扫"稳态接受域"，不覆盖抖动/相位/逐帧漂移类拒锁机理
  （那类问题由 DIAG18 df 窗口读数的稳定性另行判读）
- gap 运行中改值从下一行/帧界生效，无软复位，切换瞬间不撕裂
