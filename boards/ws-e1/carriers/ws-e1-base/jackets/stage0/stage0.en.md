# Stage-0 — ws-e1 + ws-e1-base Skeleton Project

`stage0` is the minimal runnable project generated by the EvoVerse SDK (`evoverse new-project`) for the `ws-e1` module board + [ws-e1-base](../../ws-e1-base.md) carrier combination: an LED blink design that uses only the clock, reset, and LED skeleton signals, intended to exercise the complete flow of "select board & carrier → generate project → synthesis → programming → on-board observation".

This file is also the item manifest of this jacket: `jacket.ws-e1-base.stage0` was quarantined during initial import for lacking a manifest, and has been promoted to `active` since 0.9.1.

## Hardware Resource Usage

Skeleton signals are resolved from the carrier pin map:

| Signal | Direction | Pin | Bank | Level | On-board Resource |
|---|---|---|---|---|---|
| `clk_50m` | in | T18 | TL | 3.3 V LVCMOS | 50 MHz system clock |
| `arst_n` | in | H21 | 2C | 1.8 V (bank default) | Active-low reset button |
| `led_user` | out | F21 | 2C | 1.8 V (bank default) | User LED |

Note that the voltages are mixed: the clock is in the 3.3 V TL bank (explicit `3.3 V LVCMOS`), while the reset and LED are in the 1.8 V 2C bank (no IO_STANDARD explicitly set in the ISF; they inherit the bank's 1.8 V default). Carrier bank voltage definitions: 2A_2B, 2C, 3A, 3B, 3C, 4A, 4B, 4C are 1.8 V; BL, BR, TL, TR are 3.3 V.

## Design Notes

`rtl/top.v` (top level `ws_e1_base_stage0`) is purely synchronous single-domain logic:

- A 24-bit counter counts on the rising edge of `clk_50m` and is cleared asynchronously by `arst_n`;
- The counter MSB `cnt[23]` directly drives `led_user`, completing one blink cycle in about 0.34 s at 50 MHz.

No PLL and no other IP dependencies — the minimal load for verifying the health of the ws-e1 core board + ws-e1-base carrier combination.

## File List and Generation

```text
stage0/
├── rtl/top.v                         # 骨架 RTL（自动生成）
├── constraints/
│   ├── ws_e1_base_stage0.pins.isf    # 管脚与 bank 电压（自动生成）
│   └── ws_e1_base_stage0.sdc         # 主时钟约束（自动生成）
└── ws-e1-base-stage0.xml             # Efinity 2026.1 工程（自动生成）
```

All files are generated by the SDK from the carrier pin map — **do not edit them by hand**. The timing constraints declare only the primary clock: `create_clock -name clk_50m -period 20.000 [get_ports clk_50m]`.

To adjust pins, modify the carrier pin map and regenerate. To carry real functionality, use [golden-top](../golden-top/golden-top.md), [sensor-fusion](../sensor-fusion/sensor-fusion.md), or the demo projects under the carrier instead of modifying stage0.

## Build and Programming

1. Open `ws-e1-base-stage0.xml` with Efinity 2026.1.
2. Run Synthesis → Place & Route → Generate Bitstream in order.
3. After programming and power-up, the user LED blinking with a period of about 0.34 s indicates a pass; if the LED stays off, first check the core board seating orientation, the clock bank voltage level, and the reset polarity.
