# mipi-csi-tx-4k-pattern — 4K YUV Pattern MIPI CSI-2 Transmission

> Original directory: `TJ180J484_CSI_4k_2370Ma/Ti180J484_CSI_4k_2370Ma/` (mixed TJ/Ti casing
> corrected; the 2370Ma in the directory name refers to the earlier version using an SC2370M
> sensor — the current project transmits pure patterns only)

## 1. Overview

An on-chip **3840×2160 YUV422 color-bar pattern** is packed into a CSI-2 stream
(datatype 0x1E, 4 lane) by the `mipi_csi_tx_2p5g` IP and transmitted by the **MIPI DPHY TX
hard IP (MIPI_TX2)**, for verifying the CSI-2 transmit link. The receiving side can be another
board, a MIPI capture card, or a protocol analyzer.

> Project-evolution note: the directory retains many leftover files from the earlier
> "SC2370M sensor capture + iPhone7P panel display" version (`rtl/mipi_csi/`, `rtl/panel/`,
> `rtl/vga/`, etc.). **The current top level no longer instantiates those paths**; the actual
> link is defined by `rtl/top.sv`. The historical files are kept as references.

- Device: Titanium **TJ180A484S** (timing model **I3**)
- Toolchain: Efinity 2026.1.132.1.15 (pass, the newest of the three; SDC generated by the old
  2022.2 release)
- Top module: `top` ([rtl/top.sv](rtl/top.sv), default parameters 4K; comments keep the 1080p
  alternative)

## 2. Hardware Resource Usage

| Resource | Configuration |
| --- | --- |
| **MIPI DPHY TX** (`mipi_dphy_tx_inst1`, MIPI_TX2) | 4-lane CSI-2 transmission (no RX hard IP) |
| `mipi_csi_tx_2p5g` IP | CSI-2 packing, AXI-Lite status interface |
| `pll_inst2` | 27MHz → i_fb_clk, i_sysclk_div2 (pixel clock domain) |
| `mipi_tx_pll` | 50MHz → mipi_rx_cfg_clk, dphy_byte_clk (250MHz), dbg_clk, CLK_5M |
| `pll_inst3` | → i_fb_50m, esc_clk, mipi_ref_clk |
| GPIO | only 3 clock inputs: clk_27m, clk_50m, mipi2_refclk |
| Debugger | disabled (originally auto-instrumented ILA "la0" depth 2048; must be re-enabled manually in the GUI) |

No DDR, no soft core, no MIPI RX.

## 4. Working Principle

```
video_pattern_gen（3840×2160 YUV422，i_sysclk_div2 像素时钟域）
    ↓ w_vs/w_hs/w_valid + yuv_data[63:0]
mipi_csi_tx_2p5g IP（CSI-2 打包，datatype=0x1E YUV422 8bit，4 lane）
    ↓ PPI（TxDataHS0..7 / TxRequestHS / TxReadyHS / ULPS / ESC）
mipi_dphy_tx_inst1（MIPI_TX2）→ MIPI 连接器发出 4K CSI-2 流
```

The top level also contains an AXI-Lite read-only FSM polling the TX IP status
(`r_tx_axi_araddr_1P`); `reset_ctrl` handles multi-clock-domain reset synchronization.

## 5. Build, Program, and Verify

1. Open `project_new/top.xml` in Efinity, build, and program;
2. Verification (any of the following):
   - receive the pattern with a MIPI capture card or another board (the RX project of the
     mipi-csi-rx-sc850sl demo can be referenced) and check the 4K resolution and color-bar
     content;
   - check lane rate, datatype 0x1E, and frame timing with a MIPI protocol analyzer;
   - observe the w_r/w_g/w_b/w_vs/w_hs/w_valid waveforms with the Efinity Debugger ILA (la0)
     (the Debugger must be re-enabled manually in the GUI).

## 6. Integration Notes for Customer Systems

- **Replacing the pattern with a real data source**: keep the `video_pattern_gen` output
  interface (w_vs/w_hs/w_valid + yuv_data[63:0], i_sysclk_div2 domain) unchanged; the customer
  module feeds `mipi_csi_tx_2p5g` through the same interface;
- Resolution/frame rate: top-level parameters of `top.sv` (HACT/VACT, default 3840/2160,
  comments include 1080p); after changing them, update the pixel-clock and DPHY byte-clk
  constraints in the SDC accordingly;
- The DPHY TX configuration (lane count, rate) is in `top.peri.xml` under `mipi_dphy_tx_inst1`;
- `constraints.sdc` was generated by Interface Designer 2022.2.317; its header says
  Ti180L484/C4 preliminary, which does not match the actual device (TJ180A484S/I3) — the
  constraint values have been verified on the current board, but regenerating the SDC in a new
  project is recommended when migrating;
- To enable the historical RX/panel paths (for sensor→panel passthrough), refer to
  `rtl/mipi_csi/` and `rtl/panel/`, and add the MIPI RX hard IP and GPIOs in the peri.

## 7. Known Issues and Notes

- The `check_pass`/`frame_stable` signals in top.sv are **declared but never driven**
  (leftovers after the receive chain was removed); the `led_ctrl` LEDs do not actually reflect
  the test result — only the en={00} heartbeat is controllable;
- The 4 signals `w_mipi_rx_vs/hs/de/data` are declared but unused; `led/irq/lcd_power_en/
  o_lcd_rstn` are not declared in the port list (implicit wires, left floating);
- `mipi_csi_top.sv`, `efx_dsi_tx_top.sv`, `vid_info_det_v6.v`, `Hard_csi_rx`, and
  `async_fifo_16` are in the project list but not instantiated by the top level (pruned by
  synthesis; dead code kept as references);
- The whole subtrees `rtl/vga/`, `rtl/panel/`, `rtl/color_bar_v2.0/`, and
  `rtl/mipi_csi/cam_i2c_ctrl/` are not in the project; they are historical-version leftovers;
- This reorganization removed: `ip/dsi_tx/`, `ip/soft_csi/` (neither was in the project
  ip_info), the devkit reference projects embedded in each IP directory,
  `~$DSI porch cal.xlsx` (Excel lock leftover), and `modelsim.ini_new` (duplicate simulation
  config); `DSI porch cal.xlsx` and `modelsim.ini/sim.do/wave.do` are kept.
