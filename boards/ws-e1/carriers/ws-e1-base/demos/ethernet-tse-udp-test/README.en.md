# ethernet-tse-udp-test — Gigabit Ethernet TSE MAC Test-Frame Generation / Loopback

> Original directory: `TJ180A484_TSE/TSE/`

## 1. Overview

An Ethernet test platform built on the Titanium **TSE (Tri-Speed Ethernet) hard-IP MAC** +
Sapphire RISC-V soft core:

- **Test-frame generation**: after the RISC-V configures parameters via APB3, the FPGA generates
  configurable **UDP test frames** (destination/source MAC, IP, ports, packet length, IPG, and
  packet count are all configurable) or raw MAC frames, sends them through the RGMII PHY to the
  Ethernet port, and the PC verifies them with Wireshark;
- **Loopback mode**: an AXI4-Stream mux switches the RX stream across clock domains back to TX —
  whatever the peer sends is returned — for link connectivity testing.

This demo **does not use DDR**; it is a direct reference for TSE hard-IP + RGMII + MDIO
integration.

- Device: Titanium **TJ180A484S** (C4)
- Toolchain: Efinity 2025.1.110.4.9 (pass, bitstream generated)
- Top module: `temac_ex` ([temac_ex.v](temac_ex.v))

## 2. Hardware Resource Usage

| Resource | Configuration |
| --- | --- |
| **TSE MAC hard IP** (`test_tse`, generated by efx_ipmgr, IP v4.3) | Upstream AXI4-Stream RX/TX (8-bit) + AXI4-Lite CSR + MDIO; downstream RGMII (DDIO double-edge `_HI/_LO`); `tx_mac_aclk=125MHz` |
| `pll_0` (PLL_TL0) | 50MHz → four outputs 50/125/125(90°, RGMII TXC)/25MHz |
| Soft core | Sapphire SoC (APB3 master): `reg_apb3` custom CSR + `apb3_2_axi4_lite` bridge accessing the MAC CSR |
| RGMII GPIO (1.8V, DDIO) | rxc=GPIOL_29 (+15delay), rxd[3:0], rx_ctl, txd[3:0], tx_ctl, txc; MDIO: mdc/mdio=GPIOR_35 |
| UART | rxd/txd=GPIOL_01/02 (3.3V) |

Board-level peripherals: **RTL8211FD gigabit PHY** (RGMII + MDIO), RJ45 port, SW6 DIP switch
(direct PHY reset: `phy_rstn = sw6`), UART.

## 4. Working Principle

```
发送路径（两级 mux）：
  udp_pat_gen / mac_pat_gen ──(pat_mux_select)──▶ axi4_st_mux ──(axi4_st_mux_select)──▶ TSE MAC ──RGMII──▶ PHY ──▶ 网口
  mac_rx2tx（RX 环回）───────────────▲

控制路径：
  Sapphire(APB3) ──▶ reg_apb3（mux/pattern CSR） 
                 ──▶ apb3_2_axi4_lite ──▶ TSE MAC s_axi（MAC 自身 CSR，aclk=50MHz）
```

- `pat_mux_select`: 0 = UDP frames, 1 = raw MAC frames;
- `axi4_st_mux_select`: 0 = test frames, 1 = loopback;
- The SW6 DIP switch directly pulls `phy_rstn`, allowing on-site PHY reset to observe link
  re-establishment.

## 5. Run and Verify

1. Open `temac_ex.xml` in Efinity, build, and program;
2. Connect the Ethernet port to a PC; run the `tseDemo` program (UART interactive) to configure
   frame parameters and start transmission;
3. Capturing the UDP/MAC test frames with the specified parameters in **Wireshark** means PASS;
4. Loopback verification: set `axi4_st_mux_select=1`, send packets from the PC, and observe them
   returned unchanged;
5. Check status prints on the UART console.

## 6. Integration Notes for Customer Systems

- **The TSE hard-IP configuration is defined by `temac_ex.peri.xml`**: all RGMII pins are 1.8V
  DDIO, rxc uses internal +15delay, and TXC uses the 125MHz 90° phase-shifted clock — this is
  the standard RGMII timing practice; keep it when porting;
- `test_tse.v` is an IP generation artifact; change configuration by regenerating in the
  Efinity IP UI rather than editing by hand;
- `reg_apb3` (CSR offsets TSEMAC_CSR+0x208~0x230) together with the two muxes forms the minimal
  controllable transmit framework; the customer's business data source simply takes the place
  of `udp_pat_gen`;
- The driver for PHY register read/write over MDIO is the software-side `rtl8211fd_drv.c`;
  when changing PHYs, modify this file;
- The onboard PHY is RTL8211FD; if the customer schematic uses a different PHY, note that the
  RGMII delay mode (PHY-side internal delay vs. FPGA-side +15delay) must be adjusted
  accordingly.

## 7. Known Issues and Notes

- `rgmii_2_rmii.v` and `DaulClkFifo.v` are not instantiated but remain in the project
  design_file list and participate in synthesis (they will be pruned; no functional impact —
  historical legacy);
- The SDC file name `timing_Ti60.sdc` comes from the Ti60 reference design; its content is
  valid for the TJ180A484S, and the naming is misleading legacy;
- This reorganization removed the embedded T120F324/Ti180M484/Ti60F225 devkit reference-project
  copies under `ip/`; the core IP files (settings.json, tmpl, top wrappers) are kept, and
  opening the project is unaffected.
